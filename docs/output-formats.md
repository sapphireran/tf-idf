# Output formats

Every generated table is UTF-8-ish ASCII text with **tab** separators. There is no JSON and no header on the TF / IDF / TF-IDF files.

## `output/tf/<book>.txt`

One row per distinct term in that book.

```
term<TAB>tf
```

- `term` is the token after cleaning.
- `tf` is `count / tokens(book)`, Perl default float formatting.
- Rows are sorted by `term` ascending, not by score.

Example, from `output/tf/carroll-alice.txt`:

```
a	0.0235927152317881
abide	3.76279349789284e-05
able	3.76279349789284e-05
alice	0.0144867549668874
```

A term that never occurs in the book is **absent**, not written as zero. The TF file is a sparse vector.

## `output/df.txt`

Header plus one row per collection term:

```
word \t #docs it exists in \t doc names
term<TAB>df<TAB>file1.txt, file2.txt, …
```

- The header is literal (it includes spaces around the first two tabs).
- `df` is an integer, `1 … N`.
- File names are the Gutenberg basenames, comma-space separated, with a trailing comma-space.
- Order of names is hash-key order from Perl — **not** alphabetical and **not** stable across Perl versions. Do not diff `df.txt` across machines and expect only numeric changes.

Example:

```
1	7	melville-moby_dick.txt, whitman-leaves.txt, shakespeare-macbeth.txt, austen-persuasion.txt, shakespeare-caesar.txt, chesterton-ball.txt, austen-sense.txt,
alice	3	chesterton-thursday.txt, carroll-alice.txt, edgeworth-parents.txt,
```

Confirm any row with `grep -w '^alice' output/df.txt`. Filename order is not stable.

## `output/idf.txt`

```
term<TAB>idf
```

No header. Same term order as the keys of the DF hash, sorted (`sort keys %df`). `idf = ln(N / df)` with the `N` discussed in [pipeline.md](pipeline.md).

Example hapax:

```
00	2.89037175789616
```

Example term present in 7 books:

```
1	0.944461608840852
```

Example collection-wide word (IDF exactly `0`, printed as `0`):

```
a	0
```

## `output/tfidf/<book>.txt`

```
term<TAB>tf*idf
```

Same term set as the matching `output/tf/<book>.txt`, same alphabetical order. Script 2 does not drop zeros, so `the	0` is a real row whenever `the` occurred in that book.

Example, from `output/tfidf/carroll-alice.txt`:

```
a	0
alice	0.0259568…
gryphon	0.00454724…
```

## `output/df-sorted.txt`

Present in the tree, about 3.6 MB. The current two Perl scripts do not write it. Treat it as an old artifact. Prefer `df.txt` plus `sort -t $'\t' -k2,2nr output/df.txt` if you want DF order.

## Reading the tables

### Highest-scoring terms in one book

The files are alphabetical. Use the helper:

```bash
python3 examples/python/extract_top_terms.py output/tfidf/carroll-alice.txt -n 20
```

Or POSIX tools:

```bash
sort -t $'\t' -k2,2nr output/tfidf/carroll-alice.txt | head
```

Beware: `sort` without `n` will rank `9e-05` above `0.02` because it compares strings. Always use `-n` / `-g`.

### Confirm a single identity

Pick a term that occurs in one book, for example `gryphon`:

```bash
grep -w '^gryphon' output/tf/carroll-alice.txt
grep -w '^gryphon' output/idf.txt
grep -w '^gryphon' output/tfidf/carroll-alice.txt
```

The third number should equal the product of the first two, within float printout noise.

### Collection size from the tables

```bash
# documents that contributed TF files
ls output/tf/*.txt | wc -l

# vocabulary size
wc -l output/idf.txt
```

Those should be 18 and 57368 for the committed run.

## Compatibility with the Python example

`examples/python/tfidf_example.py` writes the same four shapes (`tf/`, `df.txt`, `idf.txt`, `tfidf/`) into a directory you choose. Differences you should expect versus Perl:

- float formatting (`0.16666666666666666` vs `0.166666666666667`)
- DF filename order
- `N` defaults to the number of input documents, not `$#files`

The tiny-corpus `expected/` files were generated by the Python example with `N = 3` so they can be diffed against a rerun of that script.
